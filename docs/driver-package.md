# Experimental kernel-driver package

`driver/phoebus.inf` is original package metadata for `PhoebusW11.sys`. It matches only the Phoebus HDA function ID and targets amd64 Windows build 22000 onward. This OS decoration controls eligibility, not a claim of compatibility or certification on every listed build. Version `0.1.0.0`, dated 14 October 2026, is development metadata.

The three proposed hardware routes are speakers, headphones and S/PDIF PCM. Each has a separate WaveRT/topology pair and one endpoint, so each topology interface has its own relative `EP\0` property store. The default is 48 kHz, 16-bit stereo PCM. Its 48-byte OEMFormat value includes the serialized property header and 40-byte WAVEFORMATEXTENSIBLE. Only register a route if discovery and format validation permit that baseline. Notification mode is declared because the driver implementation is intended to use actual HDA bus notification events through IMiniportWaveRTStreamNotification; it must never be shipped with placeholder notifications.

The new package has no legacy C-Media APO registrations, GX executable, Dolby machine-wide settings, recording endpoint, Dolby/DTS encoder claim, arbitrary hardware amplifier gain, or claimed DRM certification.

The [Microsoft SysVAD base INF](https://github.com/microsoft/Windows-driver-samples/blob/main/audio/sysvad/TabletAudioSample/ComponentizedAudioSample.inx) provides the public model for the KS/WDMAUDIO registration, interface categories, DriverStore location and WaveRT endpoint properties. The new package uses a physical HDA match rather than the sample's virtual-device identity. The default-format serialization follows [Microsoft's OEMFormat documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/pkey-audioengine-oemformat).

For a manual package build, first compile the project's amd64 source with the documented WDK/toolchain and copy the resulting `PhoebusW11.sys` beside a staging copy of this INF. Update/stamp the staging INF's actual package date/version when files change. Run the installed WDK's InfVerif against the INF and Inf2Cat against the complete staging directory. Select an OS identifier that the installed Inf2Cat version actually supports; check `Inf2Cat /?`. No 26H2 identifier is invented here. [Inf2Cat documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/inf2cat).

Inf2Cat creates an **unsigned** `phoebus.cat`; creation and validation do not sign it or prove hardware correctness. Arrange the applicable development or production signing process before deployment and verify the resulting package. Do not copy the vendor catalog into this package, and regenerate the catalog after any INF/SYS change. Existing system drivers supply PortCls/KS through `ks.inf` and `wdmaudio.inf`; third-party copies are unnecessary. [Microsoft driver signing](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/driver-signing).

No driver installation, test-signing system change or target hardware test was performed. The native build now runs InfVerif `/w /v` and Inf2Cat `/nocat`; both passed locally without errors or warnings for the supported 21H2/22H2/24H2 identifiers. A distinct 26H2 check, catalog/signing and hardware validation remain outstanding. See [driver status](driver-status.md).
