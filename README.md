# Phoebus4eva

Open-source experimental Windows 11 PCM driver and read-only diagnostics for the ASUS ROG Xonar Phoebus sound card.

**Developer preview: unsigned and not tested on a physical Phoebus. Normal Windows 11 installation is not supported by the current download. Audio output, game glitches and S/PDIF lock have not been validated.** Compilation, tests and package checks do not establish kernel/runtime safety.

The project is public so the implementation, build procedure and failure paths can be audited and improved. It is not an ASUS, C-Media or Dolby release and is not endorsed by those companies.

### Installation status

**Extracting the preview does not install it. It has no phoebus.cat, Microsoft signing submission or hardware qualification.** Windows kernel/PnP signing requirements are separate from compilation. See [Microsoft's signing requirements](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/kernel-mode-code-signing-requirements--windows-vista-and-later-).

Qualified developers must arrange an appropriate signed test environment and a recoverable test machine. This project does not change boot security, trust certificates, enable test mode or bypass driver-policy checks. A download is provided for inspection and development, not represented as ready for ordinary installation.

After a future package is hardware-tested and appropriately signed, it can use the normal driver-store workflow. This illustrates that future process; **do not use it to install this unsigned preview**:

~~~powershell
# Administrator PowerShell; future complete, verified signed package only:
pnputil /add-driver .\phoebus.inf /install
~~~

PnPUtil does not force a lower-ranked driver onto a device. Follow [Microsoft's PnPUtil reference](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax), retain a verified backup and record the new published INF name before any future deployment. Device Manager rollback or restoring the saved package may be necessary. Do not remove a guessed oemNN.inf or override a hardware/signature mismatch.

## Exact hardware and feature scope

The INF matches only:

~~~text
HDAUDIO\FUNC_01&VEN_13F6&DEV_8888&SUBSYS_104384D5
~~~

The kernel also checks codec identity 0x13f68888, subsystem 0x104384d5 and the audio function-group type. The INF allows amd64 build 22000 onward; this eligibility range is not a compatibility promise. Other Xonar models, x86 and ARM64 are not supported. A diagnostic controller match does not broaden the driver's binding.

| Feature | Implemented scope | Current evidence |
| --- | --- | --- |
| Speakers / headphones | Discovered direct pin-to-DAC stereo PCM routes | No audible, socket, amplifier or gain test |
| S/PDIF | Digital stereo PCM, non-audio flag cleared | No receiver lock/rate test |
| Rates | Supported subset of 44.1/48/88.2/96/176.4/192 kHz | Capability logic tested; hardware output untested |
| Precision | Advertised 16-bit PCM; 24 valid bits in a 32-bit container | Packed 24-bit rejected; host format tests pass |
| Notifications | Real HDA DMA events and position registers | No physical interrupt/DMA trace |
| Endpoint conflicts | Exclusive reservation of shared converters | Hardware concurrency untested |
| Power / removal | Serialized state, D0 gating, route restore, engine/buffer lifetime handling | Sleep, resume, concurrent close/removal and failure stress untested |
| Multichannel / recording | Not implemented | No 5.1/7.1 analogue, microphone or line-input endpoints |
| Dolby/DTS / encoded passthrough | Not implemented | No proprietary encoder or effects included |
| Hardware volume / gain / jack sensing | No user controls implemented | Shared-mode software volume may exist; exclusive behaviour untested |
| Worms Armageddon / World of Warcraft clicks | No confirmed diagnosis/fix | Needs reproducible before/after tests |
| Windows 11 26H2 | Intended documented-API compatibility | Exact target-build runtime/signing acceptance untested |

Discovery accepts bounded direct short-form connections to usable DACs. It skips long/range entries and unresolved mixer/selector graphs. A route is registered only if it supports the INF's 48 kHz/16-bit stereo default. No usable route means STATUS_NOT_SUPPORTED; unsupported routing can produce no endpoints or no sound. Standard codec programming alone does not prove the board's external amplifiers are configured.

Portable protocol helpers support more formats than the endpoints advertise. Capability/format acceptance does not establish playback quality or receiver support. S/PDIF PCM is separate from compressed surround encoding.

## Self compile

Requirements: x64 Windows, Windows PowerShell 5.1+, Python 3.11+ and internet access for first setup. About 430 MB is downloaded; extracted tools and outputs require additional disk space. No sound card or administrator rights are normally needed for compilation/host tests.

Inspect the source, scripts and dependency lock first, then:

~~~powershell
git clone https://github.com/b1naryblaz3/Phoebus4eva.git
Set-Location Phoebus4eva
python .\scripts\setup-native-toolchain.py
python .\scripts\setup-native-toolchain.py --verify-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-native-driver.ps1 -Target All
~~~

The execution-policy option applies to this PowerShell process, not machine-wide policy or kernel security. Use your organization's approved script policy where applicable.

| Component | Pin |
| --- | --- |
| MSVC | Compiler 19.44.35229; directory 14.44.35207 |
| SDK / WDK packages | 10.0.26100.6584 |
| Kit directories | 10.0.26100.0 |
| Minimum API level | NTDDI_WIN10_CO; _WIN32_WINNT=0x0A00 |

The lockfile records eight exact Microsoft package URLs, sizes and SHA-256 digests. Setup permits its listed HTTPS origins, verifies archives before extraction and rejects escaping archive paths. Tools stay under vendor/native-tools; there is no Visual Studio installation, global PATH change or package-install hook. Microsoft's terms still apply.

The verify-only option checks cached archives, not every extracted file. Re-extract verified archives or inspect executable signatures if the tool directory may have changed. These checks are not a signed supply-chain guarantee. Custom destinations use setup --root and build -ToolchainRoot.

The native script uses /std:c++17 /kernel /GR- /EHs-c- /GS /Qspectre /guard:cf /W4 /WX and links the explicitly listed Microsoft libraries: ntoskrnl.lib, hal.lib, portcls.lib, ks.lib and BufferOverflowFastFailK.lib. It runs host tests, compiles/links, copies the INF, runs InfVerif /w /v and Inf2Cat /nocat. Warnings are errors. No target installs or signs a driver.

Outputs under dist/driver include SYS, INF, PDB/map/object files and test executables. Target Tests runs only host tests; Target Driver builds/validates only the kernel package. Symbols/maps aid manual debugging. Timestamps, debug paths and environment can change binary hashes: this is a documented repeatable procedure, not a byte-for-byte reproducibility claim. See [manual commands](docs/build-driver.md) and [package metadata](docs/driver-package.md).

## Architecture and audit map

The driver uses PortCls WaveRT and documented HDAUDIO_BUS_INTERFACE_V2 with official WDK types. It consumes Windows' bus interface, not its own controller driver. Codec/DMA calls use the returned opaque context. The card-vendor installer/archive is not a build dependency.

| Source | Responsibility | Audit focus |
| --- | --- | --- |
| DriverEntry / AddDevice / StartDevice | PortCls setup, device extension, adapter and endpoint registration | Partial-start unwind and lifetime |
| Adapter::Attach / Discover | Interface query, identity/capability checks and route selection | Response validity, node bounds, inheritance, unsupported graphs |
| Adapter::Verb / Configure / Unmute | Pool-resident serialized requests, format/stream/pin/digital controls | PASSIVE_LEVEL, masks, amplifier capability and missing board controls |
| Wave / Topology | Two-pin descriptors, range intersection and physical connections | Buffer bounds, formats, category/endpoint association |
| Stream | Real DMA buffer/engine, state, positions and events | Size/alignment, stop/reset, error ownership and event lifetime |
| Adapter::Remove / Pnp | Stream registry and removal serialization | Concurrent close, delayed mapped-buffer release, late callbacks |
| ph_hda_spec.h | Portable verb/PCM encoding and capabilities | Reserved bits, exact rates, valid/container precision |
| ph_dma_state.h | Hardware state planner | Pause between Reset/Run; successful intermediate and failed final calls |
| ph_position.h | Per-stream cyclic/pause arithmetic | Buffer wrap, zero sizes and stream independence |
| phoebus.inf | Exact HDA binding, service and endpoint properties | No broad matches, effects or vendor copied files |

Requests are frame aligned and capped at 4 MiB. Notification count is one or two. Streams use actual bus MDL/size/stream ID and link-position registers, with the bus-returned converter format. State changes pass through Pause as required and record successful transitions. Position queries use per-stream state and spinlocks, with no blocking codec request in that path.

Output gain uses the codec-declared zero-dB offset, not a guessed boost. Pin drive flags follow capabilities. External board GPIO/amp controls remain unverified. Adapter operations serialize stream/buffer/event/power/removal operations; separate request and register locks protect their paths. Intended lock order: operations → request mutex → register spinlock; position → register spinlock for queries. Review failure/concurrency paths, not just normal playback.

### Known safety and correctness boundaries

- **No kernel runtime validation:** the preview has not been loaded on a Phoebus. Deadlocks, invalid hardware accesses, leaks, crashes and audible defects may remain.
- **Removal lifetime split:** newer Microsoft guidance releases DMA engines before forwarding surprise removal while retaining client buffers until close; the older callback reference describes failure with a buffer still attached. The source tracks both lifetimes, but target bus behaviour needs testing. [Modern guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/managing-memory-buffers-rebalance), [FreeDmaEngine](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/hdaudio/nc-hdaudio-pfree_dma_engine).
- **Cleanup failures:** streams are retained in the adapter registry when cleanup fails. Event unregistration is attempted even when DMA reset fails and during powerdown. A retained stream does not retain caller-owned event storage; failed event-unregistration still needs a tested recovery guarantee. Retained resources may prevent unload.
- **Latency:** only bus FIFO size is reported. Other GetHWLatency delay fields are zero placeholders, not measured zero latency.
- **Power/routing:** sleep, hibernate, resume, external amp/GPIO control and jack behaviour are unverified. Rebalance/restart support is not declared.
- **Register mapping:** direct user-mode position/clock mappings are unsupported until safe mirrored pages are established.
- **Privilege:** a future installed driver runs in kernel mode. Open licensing, a small binary, scans or signatures alone do not establish safety.

See [SECURITY.md](SECURITY.md), [current status](docs/driver-status.md) and [qualification plan](docs/testing.md).

## Script behaviour

| File | Inputs/outputs | Effects |
| --- | --- | --- |
| setup-native-toolchain.py | Lock/archives → local tools/cache | Pinned downloads and local writes; no system/driver installation |
| build-native-driver.ps1 | Source/tools → tests and unsigned outputs | Runs compiler/linker, host tests and validators |
| build.ps1 | C# source → PhoebusProbe.exe | Uses Windows .NET Framework compiler |
| Collect-Phoebus.ps1 | PnP/build/process/CoreAudio queries → JSON reports | Reads local metadata and launches the read-only probe |
| verify-release.py | Manifest/files → pass/fail | File reads and hashing only |
| package-development.py | Explicit public list/build → ZIPs/hashes/metadata | Local packaging, no upload/install |
| GitHub workflows | Checked-out source → build artifacts | Downloads tools, compiles/tests on Windows runner; repository contents read permission |

There is no telemetry client, credential collection, automatic updater, driver-runtime executable download or automatic device replacement. Setup network activity is separate from driver runtime. Review subsequent changes rather than treating this description as a permanent guarantee.

## Diagnostics without installing the driver

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
.\dist\PhoebusProbe.exe --help
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Collect-Phoebus.ps1
~~~

Run collection on the Phoebus computer. The reports include Windows build, matching PnP IDs/driver metadata, selected audio processes and active playback endpoint/mix/period/format queries. No settings are changed, audio recorded/played or driver installed. A result from another machine is not target validation. Disabled/disconnected endpoints are excluded.

Reports may include endpoint/hardware-instance IDs and device/process names. Inspect/redact before sharing; reports are ignored and excluded from releases. A process being present does not identify a glitch's cause. Format support does not prove receiver compatibility. Probe exits: 0 successful inspection, 1 invalid arguments, 2 error/incomplete, 3 no matching active endpoint.

The binary ZIP also includes dist/PhoebusProbe.exe and scripts/Collect-Phoebus.ps1, so diagnostic collection can run without compiling. Verify a fresh extraction before using it. Generated reports are extra files and will intentionally fail a later strict archive-manifest check; re-extract separately to repeat download verification.

## Validation and hardware qualification

Local checks passed: warnings-as-errors compilation/linkage, **9,315 protocol/format checks**, **34 DMA ordering/failure checks**, cyclic-position tests, InfVerif and Inf2Cat's supported Windows 11 21H2/22H2/24H2 signability checks. The pinned kit has no distinct 26H2 identifier. No physical playback, receiver, game fix, Driver Verifier, HLK, kernel stress or resume result exists.

The SYS is x64 Native with stack-cookie protection, ASLR, NX, CFG and integrity flags. PE imports are ntoskrnl.exe, HAL.dll and portcls.sys; static Microsoft support code is also linked. The import list is not a complete license audit. Read actual [Actions results](https://github.com/b1naryblaz3/Phoebus4eva/actions); a workflow file alone proves no run passed. [Validation details](docs/validation.md).

For hardware testing use a recoverable developer machine with alternate audio. Preserve the current package and recovery route; an exported INF may omit separate utilities. Record exact OS/device/driver/game/receiver versions and reproducible baseline symptoms. Test channel identity, every rate/precision, analogue/optical paths, shared/exclusive switching, endpoint conflicts, small buffers, close/removal concurrency, sleep/hibernate/resume and error paths. Use the same Worms replay or WoW scene before/after changes. Only then proceed to qualified runtime checks, signing and ordinary deployment.
